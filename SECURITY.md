# Security Baseline and Current Limits

The capability-phase numbers below are historical; the current execution order is Phase 2 → Phase 3 → Phase 4 → Phase 5 → Phase 1 last (see `ROADMAP.md`).

## Implemented baseline (restricted catalog)

- **Sessions:** 256-bit random opaque bearer tokens, expiration, server-side SHA-256 token hashes, revocation, generic invalid-credential messages, and scrypt password hashes with per-password salts.
- **WebSocket status:** a separate 256-bit ticket expires after 60 seconds, is stored only as a hash, consumed atomically once, and is audit logged. The API checks task ownership before upgrade, publishes status-only events, filters by owner and task ID, redacts request URLs from logs, and retains authenticated polling as the reconnect fallback.
- **Authorization:** role check for administration, per-user capability grants, and independent audited grants for the two reviewed tools. Active authorization queries reject revoked or expired records. Task acceptance and every tool invocation require both the matching capability and the distinct tool grant; tool grant revocation is re-checked at call time.
- **Validation:** strict Zod schemas, bounded request/body sizes, UUID validation, parameterized SQL, and generic 500 responses without internal exception detail.
- **Rate limiting:** Fastify per-IP process-local limits, including a stricter sign-in limit.
- **Audit:** session success/failure/revocation, admin/user/capability/tool-grant operations, task acceptance/cancellation, tool invocation status, workflow-definition/run acceptance, per-step completion/failure, approval/rejection, cancellation, worker/run failure and completion, verification, and file upload/delete metadata. Records contain identifiers, statuses, counts, and safe codes—not prompts, search queries, filenames, or contents.
- **File intake (limited):** authenticated grant-gated, 32 KiB UTF-8 TXT/Markdown/log/CSV only; extension/media type and canonical base64 are checked, binary/control data rejected, filenames cannot contain paths, and API rate/body limits apply. Per-file AES-256-GCM data keys are wrapped by a server-only 32-byte key; content SHA-256 is verified before parsing, database reads/deletes are owner-scoped, and task acceptance verifies ownership. File text is not returned by upload/metadata endpoints.
- **Secrets:** environment injection only; `.env` files are ignored. No AI-provider keys are present or needed by Android.
- **Task correctness:** PostgreSQL is the source of truth; acceptance task/outbox is transactional; outbox publish uses a stable BullMQ job id; worker re-checks authorization/driver state; graph plans/nodes are checkpointed and evidence is verified before marking complete.
- **Agent Engine/tool boundary:** plans are bounded same-capability DAGs with one final node; tools cannot be selected by a model plan. The two production tools are read/search only. Each call re-checks the task owner's matching capability and distinct tool grant, validates input/output, atomically reserves a durable per-user/per-tool call quota, enforces a timeout, and audits tool name/status without writing query/file contents to the audit log. Defaults: `web.search` 20/minute and 200/UTC day; `file.read_text` 30/minute and 500/UTC day. These are call-count caps, not monetary-cost budgets; limit rejection fails closed with `TOOL_BUDGET_EXHAUSTED`. Owner cancellation reaches the worker through PostgreSQL status events and is also detected by lease refresh.
- **Recovery and evidence:** per-task database leases and node checkpoints support resume after expired-worker leases; transient upstream retry is bounded. Evidence uses an unkeyed SHA-256 chain persisted with the task; this is tamper-evident bookkeeping, not a signature against privileged database rewrite.

## Required before production

- Terminate TLS and use secure deployment secrets; rotate credentials and apply least-privilege database/Redis identities.
- Replace process-local rate limits with a shared/distributed policy before horizontal scaling.
- Add login/session anomaly controls, MFA or an identity provider, account recovery, session listing, and administrative access review.
- Add request correlation/retention policy for audit logs; avoid storing sensitive prompts or file contents in logs.
- Define key rotation, retention, encrypted backup/restore, and deletion semantics for encrypted files; add malware scanning/content sniffing/archive limits before enabling richer document or binary formats.
- Complete and live-verify isolated ephemeral code execution with CPU, memory, hard disk, process and network limits before enabling Coding/Project. A Docker/gVisor adapter exists, but no workspace/archive manager, hard disk quota, Coding driver, image/runtime provisioning, or real execution is available; leave those capabilities unavailable.
- Apply/review all migrations including `004_agent_execution_engine.sql`, `005_tool_grants.sql`, `006_tool_usage_budgets.sql`, `007_workflow_definitions.sql`, and `008_workflow_runs.sql`, and `009_provider_usage_ledger.sql`; test concurrent task/run lease claims, quota reservations, workflow version/run creation, approval races, expiry, cancellation delivery, worker redelivery/checkpoint resume, tool-grant revocation, audit persistence, Redis ACL/TLS, monitoring, alerting, backup and restore against live services.

## Explicitly not enabled

No live AI provider or model weights are configured in this repository. Server-side adapters support OpenAI-compatible gateways, Anthropic Messages/Models, and Google Gemini generateContent/Models; provider API keys are required only in server-side configuration, with Gemini's key sent in a header rather than its URL. These adapters have fetch-double tests but no live account has been verified. The read-only model catalog requires authentication (ADMIN for full profile inventories), is rate-limited on the admin route, rejects redirects, bounds provider responses and timeouts, and emits only sanitized model IDs and stable errors; it never returns provider URLs or credentials. The user route exposes only routed model names. The optional model planner (`AI_PLANNER_PROVIDER`) receives task text only through the explicitly named profile; the offline default emits one node. Planner output cannot cross capabilities or choose tools. Separately, the Web Research driver exposes exactly one provider-native function, `web_search`; it rejects missing, unknown, and multiple calls, and maps its bounded query only to `web.search` through Tool Manager. Provider adapters never execute functions. The Tool Manager rechecks grants, validates tool output, reserves quota, times out the call, and records content-free audit events; Anthropic continuation blocks and Gemini thought signatures are retained only in the server-side model round-trip. No other driver receives tools. Only `web.search` and owner-scoped `file.read_text` are registered; both require independently administered tool grants in addition to capability grants, with per-call rechecks and persistent per-user/per-tool call quotas (20/minute and 200/UTC day for search; 30/minute and 500/UTC day for file reads). These quotas do not track provider tokens or monetary costs. No arbitrary shell/browser tools, broader catalog, distributed monetary cost budgets, or model-selected workflow tools are enabled. The workflow runner accepts only validated owner-scoped immutable versions over four existing capabilities, preflights all grants and readiness, rechecks each step at execution, runs up to four independent ready DAG steps concurrently with bounded retries/output and evidence verification, and persists leases/checkpoints through a separate outbox. `approvalRequired` is enforced: the run pauses before that step until its owner approves or rejects; the owner can also cancel, with abort polling through the worker lease heartbeat. Run polling and status-only SSE are owner-scoped and omit prompts and step outputs; SSE polls durable state and is not a database push stream. Approval gates all side effects in the ready layer. Migration `008_workflow_runs.sql` and actual PostgreSQL/Redis recovery remain unverified against live services. File Analysis is limited to owner-scoped UTF-8 TXT/Markdown/log/CSV files up to 32 KiB, encrypted in PostgreSQL; it remains unavailable without `FILE_ENCRYPTION_KEY`, the explicit `AI_FILE_ANALYSIS_PROVIDER` model route, and both required grants. When a user starts an authorized analysis task, extracted file text is sent to that selected model provider. PDF/Office/image parsing and malware scanning for richer uploads are not implemented. Coding/project drivers and sandbox execution remain unavailable: only a non-integrated Docker/gVisor adapter exists, with no hard workspace disk quota or live runtime. Long-term memory/RAG, external artifact storage and S3 are not implemented. A content-free per-user ledger now records model token usage and accepted Tavily requests, with server-configured estimated rates and owner/admin summary APIs; migration `009` has not been applied or live-tested, unknown rates stay unpriced, and no monetary budget/enforcement or invoice reconciliation is implemented. Web Research requires an explicit Tavily configuration and sends its query/source content outside the private environment; it remains off until approved and configured. The private Compose stack is a deployment starting point—not live-tested—and still needs production secrets, TLS termination, image pinning, host hardening, and deployment review.
