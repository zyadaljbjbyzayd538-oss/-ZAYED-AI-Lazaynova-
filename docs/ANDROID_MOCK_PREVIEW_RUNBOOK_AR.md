# دليل Mock & Preview لتطبيق Android

هذا المسار يجهّز اختبار العرض محليًا، ولا يثبت جاهزية خادم أو مزوّد نماذج. أي نتيجة من `mockDebug` هي fixture مصطنعة.

## المتطلبات

- JDK 17.
- Android SDK Platform 37 وBuild Tools 36.0.0.
- Gradle 9.4.1 أو ملف wrapper صالح في `android/gradlew`.
- اتصال Gradle بالمستودعات الرسمية لتنزيل التبعيات؛ لا حاجة لمفتاح AI.

لا يتضمن هذا المستودع wrapper حاليًا. CI يهيئ Gradle 9.4.1 ثم يولّد wrapper مؤقتًا أثناء job. السكريبت المحلي يختار `android/gradlew` إذا كان قابلًا للتنفيذ، وإلا يستخدم `gradle` المثبت.

## اختبار المحاكاة وإنتاج APK

من جذر المستودع:

```bash
bash -n scripts/build-android.sh
scripts/build-android.sh
```

ينفّذ السكريبت بالترتيب `:app:ktlintCheck` و`:app:detekt` و`:app:testMockDebugUnitTest` و`:app:assembleMockDebug`. عند نجاح جميعها ينسخ الملف إلى:

```text
artifacts/android/Lazaynova-mock-debug.apk
```

المجلد محلي ومتجاهل في Git. إذا غاب Gradle/wrapper أو Java، يتوقف السكريبت مع رسالة واضحة؛ لا يُنشئ نجاحًا بديلًا. يمكن تثبيت APK على محاكي/هاتف اختبار يحمل Android API 28 أو أحدث، مع التحقق من ظهور شريط `MOCK` وتجربة إرسال رسالة: الرد يجب أن يحتوي علامة المحاكاة ولا يحتاج اتصالًا بالشبكة. يختلف application ID بإضافة `.mock`، فلا يشارك تخزين جلسة live.

## Flavors

| Variant | الغرض | الاتصال/البيانات |
|---|---|---|
| `mockDebug` | العرض اليدوي وCompose Preview | `BuildConfig.USE_MOCK_DATA=true`، بيانات محلية مصطنعة فقط؛ لا يُقرأ أو يُحفظ رمز دخول، ولا تُرسل رسائل |
| `liveDebug` | تكامل مع خادم اختبار/تشغيل حقيقي | `BuildConfig.USE_MOCK_DATA=false`؛ يطلب HTTPS origin وبيانات دخول من المستخدم ثم يتصل بـAPI المصادق عليه |

توجد معاينات Compose لتسعة توليفات: هاتف `<600dp`، لوحي `600–1200dp`، وعريض `>1200dp` مع Dark/Light/Cyberpunk، إضافة إلى معاينة حالة منتقي المهام. تُراجع المعاينات لتناسق التخطيط والتباين فقط، ولا تُعد اختبارًا بصريًا على أجهزة حقيقية. بيانات حساب المعاينة تتضمن أمثلة للحالات: متاح، يحتاج منحة، مستنفد، غير مدعوم في العميل، والخادم غير جاهز.

### التدفق النصي وDAG المحليان

- `MockLazaynovaRepository.streamText(...)` يعيد `Flow<String>` بمقاطع تحفظ المسافات؛ مسار الدردشة التجريبي يستهلك المقاطع تدريجيًا، ويختمها بمصدر `mock`. النص موسوم بأنه محاكاة محلية ولا يُرسل إلى خادم.
- بطاقة DAG تظهر فقط في `mockDebug`: تعرض QUEUED ثم RUNNING ثم WAITING_APPROVAL، وتعرض `UNSUPPORTED_CLIENT` و`BACKEND_UNAVAILABLE` لعقدتين محجوبتين. زر «محاكاة موافقة محلية» يكمل العرض إلى RUNNING ثم COMPLETED؛ هذا ليس طلب موافقة مالك ولا run خادميًا ولا تنفيذ أداة.
- تغطية الوحدة المضافة تتحقق من المقاطع النصية وتسلسل حالات DAG ومنع اعتماد معرف run غير صحيح. شغّل `:app:testMockDebugUnitTest` للتحقق؛ لا تعتبر كتابة الاختبار أو معاينة Compose نجاحًا إلى أن ينفذ Android build فعليًا.
- في اختبار APK بعد نجاح CI: تحقق يدويًا من التقدم وزر الموافقة المحلية، ومن بقاء العقد المحظورة محظورة، ثم كرر في أحجام `<600dp` و`600–1200dp` و`>1200dp` وسمات Dark/Light/Cyberpunk. وثّق طراز الجهاز/المحاكي ونسخة Android والـvariant؛ لا تخلط الاختبار اليدوي المحلي بنتائج backend أو موافقة نظام التشغيل.

## إعداد خادم live للاختبار

1. جهّز نشر API/worker وقاعدة البيانات ضمن runbook التشغيل الحالي، وشغّل migrations المرتبة؛ Migration `006_tool_usage_budgets.sql` مطلوبة لعدادات الأدوات. لا تتجاوز ترتيب التحقق Phase 2 → 3 → 4 → 5 → Phase 1 الحي.
2. استخدم حساب اختبار منشأً من مسار الإدارة المعتمد. امنح `CHAT` من خلال إجراءات الإدارة الحالية. منح `WEB_RESEARCH` أو `FILE_ANALYSIS` لا يمنح أداة البحث/قراءة الملف تلقائيًا؛ لكل أداة منحة مستقلة.
3. ثبّت `liveDebug` على جهاز اختبار، وأدخل HTTPS origin وحساب الاختبار في شاشة الدخول. لا تضع كلمات مرور أو bearer tokens أو مفاتيح مزود في `BuildConfig` أو `local.properties` أو Git. لا تطلب أو ترسل أسرارًا عبر المحادثة.
4. تحقق من `GET /v1/agent/capabilities` باستخدام جلسة الحساب نفسها. يجب أن تتطابق capability grants و`ready` وtool grants والعدادات مع الخادم وقاعدة البيانات. يُعاد `Cache-Control: no-store`، وتتضمن الحصة `usedThisMinute` و`usedToday` والحدين وموعدي reset و`serverTime`.
5. لا تعتبر `/v1/usage` حصة أدوات؛ هذا endpoint يلخص الرموز والتكلفة. شاشة الحصة تحسب تقدير المتبقي من العداد وحد السياسة، وتعيد عرض الصفر اليومي عند موعد UTC من الخادم. اللقطة قد تصبح قديمة بسبب جلسة أخرى، لذا استخدم زر المزامنة ولا تعتمد عليها لفرض الإنفاذ الأمني؛ الخادم يظل صاحب القرار عند الاستدعاء.
6. تحقّق من Chat ببث حقيقي ومن مصدر/نموذج أرجعه الخادم. تحقق من ملفات/بحث/كاميرا والمهام الأخرى على أنها غير منفّذة في Android؛ منح الخادم وحده لا يوصل مهمة الهاتف ولا يطلب إذن نظام تشغيل. لا تعتبر tile أو Compose Preview تنفيذًا فعليًا.

## CI وإصدار live

الـworkflow `.github/workflows/android-build.yml` يعمل عند push إلى `main` أو فروع `arena/**` وعند pull request، ويشغّل ktlint وdetekt و`:app:testMockDebugUnitTest` و`:app:assembleMockDebug` ثم يرفع mock APK لمدة سبعة أيام. إصدار detekt المثبت `2.0.0-alpha.3` تجريبي؛ توافقه مع سلسلة Android/Kotlin الدقيقة لم يُختبر محليًا، وسيحسمه تشغيل CI. أعد مراجعة/تثبيت أداة التحليل عند تغيير سلسلة Kotlin/Gradle.

بعد نجاح CI فقط، ابنِ `:app:assembleLiveDebug` لبيئة اختبار. إصدار release يتطلب إعداد توقيع منفصل عبر secret manager/CI secrets ومراجعة سياسة الخصوصية واختبار تثبيت/تحديث على أجهزة حقيقية. لا تُسجّل أو تُوزّع APK على أنه مُختبر حتى ينجح بناء Android فعلي، واختبار حساب/خادم حي، واختبار جهاز. عند إعداد هذا الدليل في بيئة تفتقر إلى JDK/Gradle/Android SDK لا تنتج APK ولا تدّعِ اكتمال البناء.
